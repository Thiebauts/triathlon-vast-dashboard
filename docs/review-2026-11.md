# Full review of the `redesign` branch — November 2026

Reviewed: branch `redesign` at commit `f414b76`. Nothing in the app was changed; this report is the only new file.

## How the review was done

Nine reviewers worked in parallel, each on one area, and each checked their findings against the real site (a production build running locally) or against the CSV files:

| Area | What was done |
|---|---|
| Points, ranks, ties | Recomputed every place and point for all 31 races (802 rows) with an independent script and compared with the app and the rendered pages |
| PB / Debut, fastest of the day, club records | Recomputed all tags, fastest splits and the 16 club records independently |
| Season recaps, overview, athlete pages, extra events | Recomputed every recap number for 2021–2026; simulated a season in progress |
| Desktop design | Clicked through every page at 1280, 1728 and 2560, English and Swedish, with screenshots |
| Phone design and share picture | Every page at 390 and 320 with touch; exported 16 share pictures |
| Accessibility | axe-core on 15 views × 2 widths × 2 languages, 162 measured colour pairs, full keyboard pass |
| Code quality and speed | Bundle sizes, load measurements (desktop and throttled phone), dead code, dependencies |
| Translations | Key check, crawl of all visible text in both languages, Swedish proofreading |
| Tests | Real coverage numbers, 21 trial tests (12 exposed real or latent defects) |

Baseline before the review: `npm test` 94/94, `npm run build` OK, `npm run lint` clean, browser tests 90/90.
Note: `npm run test:e2e` fails on a fresh machine until a matching browser is installed (`npx playwright install chromium`); the README does not say so.

**The good news first.** The core numbers are right. Points (40/35/30, then 33 minus member place), member places, the 16 club records, every "fastest of the day" pick, every recap figure and every athlete total match an independent recomputation. Guests, youth, relay teams and DNFs never earn points or take a member place. The share picture is correct in all 16 exports. The page loads fast and does not jump.

Effort scale: **small** = under an hour, **medium** = half a day, **large** = more than a day.

## 1. Bugs that show wrong or misleading data

### D1. The 2024 cycling file contains no men — high (data)
- **What is wrong:** `data/processed_cycling_results_2024-05-21.csv` has 11 rows, all women. Every other cycling year has 16–21 men. So no man earned cycling points in 2024; the men's 2024 season is built on four races and the women's on five. The 2024 recap shows an empty men's podium, says "cycling (25 to 11) had fewer starts", and the 2025 recap says "Cycling grew the most, from 11 to 29 starts". The overview chart and all-time men's totals are affected too.
- **How checked:** counted classes in the file; the saved NyTaTime race list (`nytatime/api_examples/Get all accessible races.txt`) shows that race with 35 participants and start groups switched on, so the men's group was most likely not fetched.
- **Fix:** re-fetch the men's start group with the `nytatime` scripts (do not edit the CSV by hand). Until then, show a "men's results missing" note and leave cycling out of the 2024→2025 comparison sentence.
- **Effort:** small for the note; the data fix depends on NyTaTime.

### D2. The "all years" results list ranks old-course times against new-course ones — high
- **What is wrong:** on Results with "All years", triathlon places 1–4 are Sätila times from 2021–22 (1:00:52 …), ahead of the Inseros record 1:04:38. Swimrun mixes Sisjön 2025 with Frökens udde 2026. The split "#" ranks are pooled the same way. This breaks the rule that courses are never compared.
- **Where:** `src/components/tabs/ResultsTab.tsx:304-316` (ranking pool), `:281-287` (split ranks).
- **How checked:** opened `#results/triathlon` and `#results/swimrun` in the browser. The existing browser test "All-years view sorts by best time" (`tests/e2e.mjs:240`) passes on this and so approves the wrong behaviour.
- **Fix:** group the all-years list by course (using `COURSE_HISTORY` from `src/lib/records.ts`), with a heading per course; move the ranking into a `src/lib` function and unit-test it.
- **Effort:** medium.

### D3. Old courses never get PB tags or a course-record line, and the course notes are wrong — high
One cause, several visible effects. The code has two descriptions of the courses that disagree: `COURSES` in `src/lib/season.ts:23-30` only knows "current course" (`triathlon: { since: 2023 }`, `swimrun: { excluded: true }`), while `COURSE_HISTORY` in `src/lib/records.ts:14` models each course properly.
- **Triathlon 2022 shows "0 personal bests"** although 11 members beat their 2021 Sätila time (Jonathan Flod, Jonatan Hägerström, Jan-Åke Kjellberg, Jan Ljungcrantz, Ronny Rosén, Karl Wackerberg, Magnus Jönsson, Fredrik Überbacher, Anna Svensson, Ellinor Nilsson, My Forsberg). The 2022 season count of 18 personal bests leaves triathlon out.
- **No "Course record" line** on the triathlon 2021/2022 and swimrun 2025/2026 result pages, although the Records page has those records.
- **Wrong note on season cards:** triathlon 2021, triathlon 2022 and swimrun 2025 all show "New course this season (three laps at Frökens udde; 2025 was at Sisjön)…" (`src/components/tabs/SeasonTab.tsx:73-75` prints the swimrun note whenever there are no records).
- **Recap sentences swapped:** 2022 says "Triathlon: … New course, so no records or personal bests are compared" (it was the second year at Sätila); 2023, the real first year at Inseros, says "No personal bests this time" and "0 of 0 members who raced it before" (`src/lib/seasonStory.ts:106-107`).
- **Time bomb for 2027:** swimrun is excluded outright, so the second race at Frökens udde will still say "new course" and get no PBs, while the Records and athlete pages will compare it.
- **How checked:** independent recomputation of all tags; rendered pages `#results/triathlon/2022`, `#season/2021`, `#season/2022`, `#season/2023`, `#season/2025`; two trial tests.
- **Fix:** give every race a course id derived from `COURSE_HISTORY`, compare only within the same course in `src/lib/raceDay.ts:23-33` and `src/lib/season.ts:122`, delete `COURSES`, and make the note sport-specific ("first year on this course").
- **Effort:** medium.

  - Duathlon 2024 shows Armando Hurtado Sandoval 16:38 as fastest Run 1 ahead of Jonathan Flod 17:03. His row is broken in the same way (legs add up to 6164 s against a 5165 s total; he finished 19th).
- **Other rows with impossible splits** (none wins a "fastest" today, but they show wrong times and distort split ranks):

- **Effort:** small for the guard, medium for the import repair.

### D5. Some members are labelled "guest" in single races and so score nothing — medium (needs the club)
The app takes membership from each CSV row. These guest rows sit between member rows for the same person:

|---|---|---|---|
| Karl Wackerberg | cycling 2026 (member in the other four 2026 races and since 2021) | about 15 pts, place 18 | 4 members lose 1 pt each |
| Jonas Örarbäck | swimming 2023 | 35 pts, place 2 | 11 members lose 15 pts in total |
| Helena Jakobsson Larsson | duathlon 2023 (and running 2021, running + swimming 2025) | 35 pts, place 2 | 4 members lose 8 pts in total |
| Maria Ernsfors | running 2023 | 23 pts | none |
| Sofia Haglund | swimrun 2025 | 30 pts, place 3 | 1 member loses 1 pt |
| Greg James-Rae | cycling 2026 | 24 pts | 13 members lose 1 pt each |

- Helena's guest rows match exactly the races where Erik Arnström was entered as a guest. Erik has a correction in the code (`src/lib/data.ts:62-64`), she does not. She was the fastest woman in running 2021 (19:51, shown as "Fastest overall: guest"); if she was a member, the 2021 women's champion changes.
- The reverse question: Erik Arnström's correction makes him a member in **every** year, though four of his six CSV rows say guest. He scores in running 2021, duathlon 2023, running 2025 and swimming 2025 and pushes members behind him down one place. Was he a member all along?

### D6. Athletes with equal points get different rank numbers — medium
- **What is wrong:** the club ranking numbers rows 1, 2, 3 … regardless of ties, and the order among tied athletes is just the order of the CSV files. Examples: 2025 women Louise Bichler #5 and Josefine Flod #6, both 63 pts; 2026 men Samuel Karlsson #11 and Melvin Johansson #12, both 62; all-time men, seven athletes on 28 pts numbered #69–#76. Over a hundred tied pairs in total.
- No tie touches a top-3 today. When one does, `src/lib/season.ts:262` (`slice(0, 3)`) will silently pick one of two tied athletes for the podium and the "congratulations" sentence.
- **Where:** `src/components/tabs/RankingsTab.tsx:37`, `src/lib/data.ts:361`.
- **Fix:** shared ranks (1, 2, 2, 4), a fixed tie-break for display order (name), medal colours by rank. Decide the rule for a tied season title.
- **Effort:** small.

### D13. Swedish text that says the wrong thing — medium
- **"150 år 2025"**: the recap sentences "Det kan jämföras med 150 år 2025" and "upp från 25 år 2025" read as "150 years". Keys `season_story_trend_prev`, `season_story_trend_avg_*` (`src/lib/translations.ts:336-341`), `ath_one_race` (`:161`). Fix: "…med 150 starter 2025", "…mot 25 året innan".
- **"Sprintlopp" for the 5 km track race** (`discipline_running_title`, `:193`); it appears on the share picture. Fix: "Löpning – 5 km banlopp".
- **"Staffet"** (from the CSV class) is a misspelling of "Stafett" and is shown as a heading and in cells.
- **Class names are shown raw:** in English the pages show "Pojkar", "Flickor", "Ungdom", "Barn 10+", "Ungdom herr", "Staffet"; the column is headed "Gender/Kön" but holds a class. `src/components/tabs/ResultsTab.tsx:46-51`, `ExtraEventsTab.tsx:141`. Fix: translate all classes in `classLabel`, use it on Extra events, rename the header to "Class/Klass".
- **Plurals:** "1 tävlingar: 32 medlemmar", "6 tävlingar: 1 medlemmar", "1 total results", "B: 1 athletes" are on screen today. Fix: a small `plural(n, one, other)` helper.
- **Recap oddities:** 2023 "122 in 2022 and 128 a year in 2021"; 2022 "raced all 4 championships, and 6 members raced four or more" (says the same thing twice); "27 personal bests of 67 members" (67 is results, not members); the 2021 page has a "2020 starts" column and legend although there was no 2020.
- **Effort:** small each; medium together.

### D14. Latent: recap text breaks during a season or with a thin race — medium (not visible today)
- **What is wrong:** simulated with only two 2026 races loaded, the page says "X and Y won the season points ranking", "Warm congratulations … winners of the 2026 season!", compares 50 starts with last year's full 150, and says "raced all 2 championships, and 0 members raced four or more". With one entrant: "raced 1 championships", "Cycling:  won the club title." (empty name). This will appear in May 2027.
- Also: the list of seasons is hard-coded (`src/lib/season.ts:12`), so Overview, Season and Records stay on 2026 until someone edits it; the overview treats a season as finished only when all six sports are raced (`src/components/tabs/OverviewTab.tsx:42`).
- Relay runners are counted for this year but not for "last year" (`src/lib/season.ts:194` vs `:199`), so the 2027 triathlon recap would compare with 13 instead of 16.
- **Fix:** a "season complete" flag with "leads" wording mid-season, singular forms, skip empty parts, one shared start-count helper, derive the season list from the data.
- **Effort:** medium.

### D15. Latent: the data loader accepts bad input silently — medium (no failure today)
None of these happen with today's files, but each would produce wrong rankings without any error:
- A status other than DNF/DNS (for example DSQ) with a time counts as a finish and scores (`src/lib/data.ts:100-104`).
- Class is compared case-sensitively in one place (`src/lib/data.ts:169`): "Herr" and "HERR" in one race would give two 40-point winners.
- Names are only trimmed (`src/lib/loader.ts:74-75`): a spelling variant splits one athlete in two. The TypeScript correction list has 3 entries, the Python one 12; the club-alias lists differ too.
- The CSV parser splits on commas with no quote handling, does not check the header, and pads short rows (`src/lib/loader.ts:41-55`). Two files for the same sport and year would double the points.
- **Fix:** normalise at load, and make the build fail on unknown status/class, missing columns, wrong cell counts and duplicate sport-years.
- **Effort:** small.

### D16. For the club to decide: same time on screen, different points
Six pairs show the same time but get different places because the stored times differ by tenths. Example: triathlon 2026, Ida Stjernkvist and Kornelia Krumkühler both 1:44:54, 35 vs 30 points; the same pair in duathlon 2026 (30 vs 29). The Points page documents this ("to the tenth of a second"), so it is not a bug — but it looks like one. Sharing places on the displayed time would make the 2026 women's season 141–139 instead of 140–133 (same winner). No code change unless the club wants it.

## 7. Design improvements (within design B)

1. **Centre the page and add a wide tier.** Centre the 1200 px column, the hero's inner block and the footer; allow about 1360 px for result tables above 1600 px. Fixes the empty right side on a MacBook 16" and on large monitors (U2).
2. **One table pattern for every page.** A shared table style in `src/components/ui/brand.tsx`: navy header that stays visible, right-aligned times, names on one line, a narrow share-icon column. On phones, one shared card pattern for Rankings, Extra events and athlete "All races", as Results already has. Solves U1, U5, U9, P2 and A10 together.
3. **One chart theme.** Charts are the most off-brand part of the site: the overview uses a rainbow palette, the season charts blue/orange/green, and there are two tooltip styles. Use navy, club red and a grey ramp, and the navy tooltip from the athlete chart everywhere. This also fixes the contrast failures (A6).
4. **A fixed set of cards and headings.** Export three card styles from `brand.tsx` (mist, navy, outline) and delete the local one in `SeasonTab.tsx:22`; keep the big corner to one level (the season page nests three). Use `SectionTitle` on every page with two sizes — headings currently come in 22, 24, 26, 30 and 34 px.
5. **Navigation that behaves like pages.** Back button returns to the previous page, every link opens at the top, the menu remembers its state, the browser tab shows the page name in the current language (U3, U4, U8, A1, A2).
6. **The athlete page as a real profile.** Name as the page title, finder collapsed to "Find another athlete", rank within the athlete's own table, a link from each race row back to that race, round chart ticks, no line between different courses.
7. **A compact phone header.** Menu, logo, search icon and language in one sticky 56–64 px row instead of 203 px. Optionally a bottom bar with the four most used pages.
8. **A results header that tells the truth.** Counts follow the class filter; the filter row is the same on Results, Extra events and Rankings; empty states say what is empty and offer "Clear".
9. **Share picture.** Add a 1080×1920 Story format; use the empty area for a second fact (gap to PB or to last year); offer sharing from athlete pages and season podiums too; attach a link to the race when sharing.
10. **A consistent order.** Rankings lists women first, every other page men first; pick one.
